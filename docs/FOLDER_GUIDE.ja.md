# フォルダーの役割と整理

## 基本構成

| 場所 | 役割と分離する理由 |
| --- | --- |
| Gitの作業リポジトリ（例：`D:\GitHub\localbrain-client`） | 正式ソース・再利用するテスト・文書。GitHubと同期する開発の正本です。 |
| `%LOCALAPPDATA%\LocalBrain\releases\<版>` | ビルド済み製品。ソース編集やpullが実行中プロセスへ直ちに影響しないよう分けます。 |
| `%LOCALAPPDATA%\LocalBrain\control-plane` | 非公開設定、DB、OCR・Slackの保存領域、起動記録。コード更新時にも保持します。 |
| `%LOCALAPPDATA%\LocalBrain`配下のモデル・OCR資産 | 大きなモデル、推論エンジン、専用Python、固定依存。毎回ビルド・複製しません。 |
| `%LOCALAPPDATA%\LocalBrain\app`・`tools` | Windowsの起動入口・操作用スクリプト。小さくても実設定から参照されていれば必要です。 |
| `%USERPROFILE%\.continue` | Continueのユーザー設定とMCP接続先。リポジトリ内の`.continue/rules`とは別の範囲です。 |
| 作業資料の`output/audit/<案件>` | 調査・テスト・承認・配備の証跡。製品や本番データから分離します。 |
| `%TEMP%`・作業用コピー・LAN共有 | 隔離試験と受渡し。終了・統合・非参照を確認できれば整理できます。 |

## 複数リリースが残る理由

Bridge、Slack Host、Continue MCP、操作ツールを機能単位で更新する場合、それぞれが異なる版を参照します。最も新しいフォルダーがあるだけで全利用元が自動切替するわけではありません。版の統一は、互換性・設定・起動経路・必要な再起動を確認する別の配備作業です。

古い日付や短いコミット名だけを理由に削除してはいけません。実プロセス、Windowsタスク、起動スクリプト、Continue設定、操作ツール、インストール記録からの参照を確認します。正確な現役版は環境固有の記録で確認してください。

## 整理できるもの

終了した公開・合成試験の一時DB、空の作業フォルダー、main統合済みで差分がなく追加worktreeもないコピー、再生成可能な旧ビルド、使用済み公開受渡しパケット、未参照の旧実行環境です。モデル・依存の重複コピーは、正本が存在し、参照されず、全ファイルのハッシュが一致することも確認します。

削除前に絶対パスが対象ルート内であること、再解析ポイントでないこと、対象が更新・使用されていないことを再確認し、一覧と削除記録を残します。最終的なビルド・配備の小さな記録は保持し、削除後に現役ファイル・設定・プロセスが変わっていないことを確認します。

## 残すもの

現役ソース、機能を守る回帰テスト、使用中のモデル・依存・認証・設定・DB・起動入口です。認証・隔離・取消・重複送信防止などは低頻度でも重要な試験です。「レアケースだから」という理由だけで削除しません。

モデルや依存環境を監査資料へ複製し続けず、原則として正本の場所・版・SHA-256を記録します。固定した監査原文や配備パケット内の文書を訳す場合も、原本ハッシュを壊さず別の日本語説明を添えます。
